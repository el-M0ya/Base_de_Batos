1. PROPÓSITO DE LA CAPA DE TESTS DE INTEGRACIÓN
-------------------------------------------------------------------------------
Las pruebas de integración verifican la interacción entre múltiples componentes
reales del sistema:
  - Repositorios SQL y consultas PostgreSQL reales (incluyendo Triggers y FKs).
  - Endpoints HTTP de FastAPI utilizando TestClient o AsyncClient.
  - Serialización y Deserialización de DTOs / Schemas Pydantic.

REGLAS DE PRUEBAS DE INTEGRACIÓN:
  - Se conectan a una base de datos de prueba (PostgreSQL en Docker o Test DB).
  - Verifican que los adaptadores (Adapters) e infraestructura funcionen correctamente.
  - Usan "Fixtures" de Pytest en conftest.py para preparar y limpiar datos de prueba.

def db_connection():
    # Proporciona una conexión real a la base de datos de pruebas.

    yield conn
    conn.close()

@pytest.fixture
def client():
    # Proporciona un TestClient de FastAPI para simular peticiones HTTP.

        yield c

def test_health_check_endpoint_returns_200(client):

    response = client.get("/health")

    # Assert
    assert response.status_code == 200
    assert response.json() == {
        "status": "ok",
        "message": "Backend service is running smoothly"
    }

# File: tests/integration/adapters/test_postgres_user_repository.py
from src.adapters.repositories.postgres_user_repository import PostgresUserRepository
from src.domain.entities.user import User, UserRole

def test_postgres_user_repository_save_and_get(db_connection):
    # Arrange
    repo = PostgresUserRepository(db_connection)
    new_user = User(id_user=None, email="test_integration@gym.com", password_hash="hash_abc", role=UserRole.TRAINER)

    # Act
    saved_user = repo.save(new_user)
    fetched_user = repo.get_by_id(saved_user.id_user)

    # Assert
    assert saved_user.id_user is not None
    assert fetched_user is not None
    assert fetched_user.email == "test_integration@gym.com"
