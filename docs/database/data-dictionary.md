## 1. Reading this dictionary

- Types, defaults, nullability, primary keys, foreign keys, inline constraints, and explicit indexes below are copied from the current table-creation scripts 001–005.
- `IDENTITY (BY DEFAULT)` means PostgreSQL generates a value when one is not supplied; an explicitly supplied value is also accepted.
- “Nullable” means the DDL does not declare `NOT NULL`; it does not imply that the application should always omit a value.
- Constraints merely attempted by script 006 are not described as successfully installed. That file currently contains table/column references which do not match the physical DDL. See §4 and [schema.md](schema.md) §7.
- Constraint names in a table definition are shown as declared. Primary keys declared inline without an explicit name use PostgreSQL-generated names.

## 4. Constraints and indexes declared by script 006: status of alignment

Script 006 is intended to add the source uniqueness/domain/temporal rules, but currently does not line up with the column names in scripts 001–005:

| Script 006 reference | Current DDL name | Impact |
|---|---|---|
| `"user"` | `app_user` | First U-1 ALTER TABLE target is absent |
| `contains.rest_seconds` | `contains.rest_time_seconds` | CHECK target is absent |
| `session.intensity_perceived` | `session.intensidad_percibida` | CHECK target is absent |
| `routine.state` | `routine.status` | Index target is absent |
| `routine.intensity_level` | `parameters_routine.intensity_level` | Index target is absent |
| `assignment.end_date` / `assignment.assignment_date` | `fecha_fin` / `fecha_asignacion` | Temporal-check columns are absent |
| `session.start_time` / `session.end_time` | `hora_inicio` / `hora_fin` | Temporal-check columns are absent |
| `session.session_date` | `fecha_sesion` | Index target is absent |

Further semantic mismatches:

- Script 006's exercise unique constraint uses `(name, id_exercise_type, id_muscle_group)`, while the source U-12 definition in `docs/requirements/informational-requirements.md` is `(exercise name, id_muscle_group)`.
- Script 006 uses `UNIQUE(id_session, id_assignment)`, which is redundant with `id_session` as primary key; the source U-10 is `(id_assignment, fecha_sesion)`.
- Script 006's routine-structure unique constraint is redundant with the table's primary key on `id_routine`.
- Script 006's `chk_parameters_counts_positive` allows zero, while script 004 requires `total_exercises > 0`.
- The `chk_validation_consistency` block is only a placeholder and adds no constraint.
- The final index `idx_session_assignment_date` references `session_date`, which is not a declared column.

Do not rely on script 006 as a successfully applied constraint inventory until these discrepancies have been resolved and the script has run against a clean database.

## 7. Requirements not represented by physical columns

These are differences between the requirements catalogue and the current DDL, not implied fields:

- Account active/inactive state: no column in `app_user`.
- Standalone room-chief relation: no `room_chief` table.
- Standalone intensity-level catalog: no `intensity_level` table.
- Exercise intensity: no column in `exercise`.
- Flexibility ratio / muscle-group coverage parameter: added to `parameters_routine` by `011_routine_parameters_full_generation.sql`.
- Routine regeneration lineage: no source-routine FK on `routine`.
- `REPLACED` routine state: excluded by `chk_routine_status`.
- Routine structure is separate JSONB, not a relational set of nested block tables.

See [schema-mapping.md](schema-mapping.md) for the 21 original relations and their status.

## 8. Verification commands

After the SQL scripts have been reconciled and applied to a clean PostgreSQL database, use these queries to capture the actual deployed schema:

```sql
-- Columns, type, nullability and defaults
SELECT table_name, ordinal_position, column_name, data_type,
       character_maximum_length, numeric_precision, numeric_scale,
       is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position;

-- Primary keys, foreign keys, unique and check constraints
SELECT conrelid::regclass AS table_name,
       conname,
       contype,
       pg_get_constraintdef(oid) AS definition
FROM pg_constraint
WHERE connamespace = 'public'::regnamespace
ORDER BY conrelid::regclass::text, conname;

-- Actual indexes
SELECT tablename, indexname, indexdef
FROM pg_indexes
WHERE schemaname = 'public'
ORDER BY tablename, indexname;

-- Actual triggers
SELECT event_object_table, trigger_name, action_timing,
       event_manipulation, action_statement
FROM information_schema.triggers
WHERE trigger_schema = 'public'
ORDER BY event_object_table, trigger_name;
```
