- **Assignees:** @el-M0ya
- **Labels:** None
- **Created:** 2026-10-14T16:52:20Z
- **Updated:** 2026-10-29T14:27:59Z

## Goal
Record the project's persistence decision and rules for storing the variable structure of training routines.

**Related epic:** #3 — [E0] Project Planning and Governance

## Files to create or modify
- `docs/architecture/decisions/ADR-002-postgresql-jsonb-direct-sql.md`
- `docs/database/storage-adaptation.md`

## Decisions to document
- PostgreSQL as the storage system.
- JSONB for variable routine structure, in an auxiliary `routine_structure` table.
- Access from Python through parameterized SQL and a PostgreSQL driver, without an ORM, according to the proposed project decision.
- Versioned SQL scripts executed in order, without adding a separate migration tool for now.

## Work
- Explain which data remains in relational tables and which flexible content is stored as JSONB.
- Document data validation, keys and relational constraints, parameterized queries, and error handling.
- Explain how scripts are versioned and run in a clean environment and how schema updates are prepared.
- Record risks and consequences, including the responsibility to keep scripts ordered and repeatable.

## Acceptance criteria
- [ ] The ADR explicitly states the decision, rationale, alternatives, and consequences.
- [ ] The separation between relational information and routine JSONB structure is documented.
- [ ] Unsafe string concatenation for queries containing user data is prohibited.
- [ ] The SQL script execution procedure is understandable and reproducible from an empty database.
